# #407 Naming Benchmark — Batch Execution Manifest

Status: execution protocol locked after G0 screening-pilot efficiency review.

Target: 100 fresh candidates per arm, 900 total.

## Funnel

1. Freeze all 900 before benchmark screening.
2. Gate A batch: authoritative `.org`, `.com` preference, exact GitHub/project, automatable exact identity, deterministic normalized variants.
3. Gate B only for Gate-A survivors: near spelling/phonetic, company/org/product/project, trademark-oriented exact+near, common-law/developer surfaces.
4. Gate C/D only for serious survivors: linguistic/cultural/pronunciation, historical/proper-name, confusing similarity, final feasibility normalization.
5. A–E + Pareto only for feasible survivors.
6. Owner Exposure Gate only after benchmark evaluation.

## Short-circuit rule

A decisive Red ends further screening for that candidate. It remains a benchmark failure and is never replaced. Equal decision logic is required across groups; equal query count for already-dead candidates is not.

## Reporting

Default Owner-facing checkpoints:
1. 900-name generation freeze;
2. full Gate-A readout;
3. final nine-arm benchmark readout.

The earlier G0/20 detailed investigation is retained as screening-instrument pilot data, not as the execution template for the remaining 880 candidates.
