# Adaptive Naming v0.3.3 → v0.4.0 Additive Migration

目的：把已经在真实 Naming Job 中运行的 v0.3.3 state 升级为 v0.4.0，而**不重新初始化任务、不重做历史轮次、不重新解释已经冻结的 Owner 约束**。

## 1. 迁移原则

- 历史 snapshot / rounds / candidates / observations / diagnostics 全部保留；
- v0.3.3 的 job-level Controller 结论不因版本升级自动失效；
- 只从已有证据恢复新字段，证据不足则 `unknown`；
- 不根据“现在觉得合理”伪造过去的 workflow pattern / region / runtime isolation；
- v0.4 新层默认是 additive metadata / control state，不要求回放全部历史；
- 迁移本身不得触发 Owner Gate。

## 2. 字段映射

### `map` → `search_landscape`

旧字段若存在：

- `initial_landscape_summary` → 原样保留；
- `regions` → 迁入 `search_landscape.regions`；
- `semantic_coverage` → 原样保留。

对历史 region 不补造 collision prior / information gain。只有已有 round/diagnosis 明确支持时再填。

### `method_scheduler` 保留但重新解释为 operator scheduler

旧 active strategy / family 不删除。它们继续代表 Construction / Search Operator 层。

新增 `workflow_scheduler`，只为当前和后续 action 记录 pattern。不要给每个历史 round 追填 pattern。

### Search cadence

根据**当前 next_action**设定：

- 明确小试 → `micro_probe`
- 多方法小批 → `portfolio_batch`
- 明确高容量发散 → `divergence_burst`
- 强方向有限深挖 → `focused_exploitation`
- 只验证不生成 → `validation_only`

历史轮次不必追填。

### Runtime profile

根据当前 runtime 事实填写，不能从过去的逻辑 blindness 推断真实隔离能力。

例如同一 ChatGPT conversation：

```yaml
runtime_capability_profile:
  shared_context_only: true
  fresh_context_available: false_or_unknown
  isolated_subagents_available: false_or_unknown
  persistent_state_io: true
```

`generation_isolation_level` 保持历史事实，如 `best_effort_same_context`。

### Preference model

只迁入重复出现、来源明确的 Owner preference。一次性 reaction 保持原 candidate / Owner signal，不升级为 stable preference。

### Experience export

已有 `experience_candidates` 不删除。只把明确具有潜在泛化价值的项目 export 到：

`evolution/method-experience-registry.yaml`

Registry 不成为 Generator input。

## 3. #411 当前迁移策略

以 snapshot v40 为历史基线：

- 不重新初始化 Organization Naming；
- 不恢复 G0–G8 benchmark；
- v0.3.3 reality / isolation / Owner Gate 结论继续有效；
- 当前 Naming search 可在 v0.4 下继续；
- 第一轮只需要：
  1. 恢复 / 初始化 `search_landscape` 的当前 frontier；
  2. 根据 `biggest_unknown` 选择一个 workflow pattern；
  3. 设定 search cadence；
  4. 记录当前 runtime capability；
  5. 再进入正常 Naming search。

不要因为 migration 本身重新生成候选。

## 4. Migration integrity check

迁移后至少确认：

- confirmed hard constraints 未增加 / 丢失；
- Owner preference 未被升级成 hard gate；
- historical candidate roles 不变；
- historical reality evidence 不被重写；
- historical isolation claim 不被抬高；
- v0.3.3 regression baseline 仍通过；
- 新字段的 `unknown` 被允许存在。
