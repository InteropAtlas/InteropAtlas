# InteropAtlas 语言策略

InteropAtlas 采用：**中文优先、英文机器标识、中英双语知识字段。**

这不是“中文项目”与“英文项目”的二选一，而是把不同语言放在最适合它们的层级。

## 1. 人类阅读层：中文优先

当前阶段的主要设计、解释、方法论和治理文档优先使用中文，以降低概念设计与讨论成本。

必要时提供英文版本，但英文版本不应反过来限制中文对复杂概念的准确表达。

## 2. 机器标识层：英文

以下内容使用稳定英文标识：

- 目录与文件结构；
- YAML / JSON 字段名；
- 稳定对象 ID；
- 枚举值；
- Relation 类型；
- Schema；
- API；
- URL slug；
- CLI 参数；
- 代码标识符。

例如：

```yaml
id: device_discovery
type: capability
```

而不是：

```yaml
id: 设备发现
type: 能力
```

这样可以降低跨平台、代码生成、RDF/图数据库、API、国际协作和第三方工具集成中的摩擦。

## 3. 知识字段：中英双语

名称、描述、定义等面向人的知识字段原则上采用成对字段：

```yaml
name_zh: 设备发现
name_en: Device Discovery
description_zh: 系统发现可用设备、节点或服务的能力。
description_en: The capability to discover available devices, nodes, or services.
```

在 v0.1 阶段，基础对象要求至少提供 `name_zh` 与 `name_en`。描述字段可以随着数据完善逐步补齐。

## 4. 官方名称优先于翻译

标准、协议、组织、产品、项目等如果存在正式名称，应保留其官方名称。

例如标准编号、商标名称或组织名称不应为了“中文化”而被改写成非官方名称。中文译名仅作为显示和理解辅助。

当 `name_en` 不能完整表达原始官方名称时，可使用：

```yaml
official_name: ...
```

保留源语言名称。

## 5. 翻译不是事实源替代品

中文译名和中文解释属于 InteropAtlas 的知识表达层，不应替代官方规范中的原始术语。

如果某个术语存在多个译法，应优先：

1. 保留官方原文；
2. 选择行业中较通行的中文表达；
3. 必要时记录别名；
4. 避免因为翻译差异创建重复对象。

## 6. 关系类型保持英文稳定

例如：

```yaml
relation: alternative_to
relation: depends_on
relation: compatible_with
relation: bridges_to
```

中文界面或文档可以分别显示为“替代方案”“依赖于”“兼容”“桥接到”。

英文关系类型是机器语义标识，中文是显示标签，两者不应混用。

## 7. 长期目标

当前中文优先是项目早期的工作语言策略，而不是永久限制社区语言。

未来可以在不改变机器模型的前提下扩展更多语言，例如：

```yaml
name_ja: ...
name_de: ...
```

如果多语言规模明显增长，再考虑迁移到统一的语言映射结构。v0.1 暂不提前复杂化模型。
