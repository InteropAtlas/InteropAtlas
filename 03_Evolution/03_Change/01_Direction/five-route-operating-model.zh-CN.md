## Historical model

早期 InteropAtlas 将建设工作组织为五条路线：

1. **Human Route** — 人如何发现、理解、探索并使用 Atlas；
2. **Machine Route** — 机器如何读取、验证、解析、查询、分析和维护 Atlas；
3. **Curation / Contribution Route** — 知识如何进入 Atlas；
4. **Trust / Provenance Route** — 来源、证据、贡献身份与可追溯性；
5. **Governance Route** — 项目如何授权、审查、演化与避免单点维护。

这一模型的重要历史贡献是把 InteropAtlas 从“数据仓库 + 网站”扩展成同时考虑人类使用、机器可用、收录、信任和治理的系统。

## Why superseded

随着 Master Design、V1 Core Architecture、Canonical Intake、Workspace、Human + Agent Access、长期路线图和独立治理 Profiles 形成，五路线已经不再适合作为同一层级的总体模型：

- Human / Machine 现在统一在 Atlas-first + shared Canonical Knowledge 下理解；
- Curation 已被 Candidate → Validation → Review → Acceptance 架构替代；
- Trust / Provenance 已形成独立 Profile；
- Governance / Task Authority 已形成独立治理边界；
- 长期路线不再由五条路线定义。

因此五路线保留为设计演化证据，而不是继续作为 Living Document。
